# Phase 24 — UI Design Contract

> Visual and interaction contract for frontend changes. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase UI Impact Assessment

**Classification: MINIMAL UI PHASE (backend-dominant)**

Phase 24 is primarily a backend refactoring phase. The two features are:

1. **Skill Focus (session-time instruction injection):** Entirely backend. Uses Azure Foundry `additional_instructions` at run level. The user sees the same conversation UI -- the agent simply behaves differently. **Zero frontend changes.**

2. **CU-based evaluation (replacing LLM scoring_engine):** Backend service replacement. The existing scoring UI already supports:
   - Dynamic dimensions via `DimensionBars`, `RadarChart`, `FeedbackCard`
   - Voice + content dual categories via `VoiceScoreSection` and `useCombinedScore`
   - Async scoring states (pending/processing/completed/failed)

**Genuine new UI elements (2 only):**
- Admin RubricEditor: Add content_weight / voice_weight category sliders (D-12)
- Scoring feedback: Show category subtotals (content subtotal + voice subtotal) before combined score

## Component Changes (not new components)

### 1. RubricEditor Enhancement

**File:** `frontend/src/components/admin/rubric-editor.tsx`
**Change:** Add a "Category Weights" section below the existing dimensions list.

**Layout spec:**
```
[Existing dimensions list]
---
## Score Category Weights          <- new section heading, 14px semibold
[Content Weight]  [====slider====]  60%    <- Slider component, range 0-100
[Voice Weight]    [====slider====]  40%    <- Auto-calculated (100 - content_weight)
                                            <- Muted helper text: "语音会话适用"
```

**Interaction contract:**
- Single Slider controls `content_weight` (0-100, step 5, default 60)
- `voice_weight` = 100 - `content_weight` (derived, not independently editable)
- Slider uses existing `<Slider>` component with `--primary` track color
- Below slider: muted text explaining voice weight only applies to voice/digital human sessions
- Spacing: 16px gap between section heading and sliders, 8px between the two weight rows

**Validation:**
- content_weight must be 0-100 (zod schema extension)
- No separate voice_weight validation needed (derived value)

### 2. Scoring Feedback Page Enhancement

**File:** `frontend/src/pages/user/scoring-feedback.tsx`
**Change:** Add category subtotal display between the overall score ring and the dimension breakdown.

**Layout spec (inserted after existing circular score ring, before 2-column grid):**
```
[Overall: 82/100]   [Content: 85/100 (60%)]   [Voice: 78/100 (40%)]
                     ^-- green if >=80          ^-- amber if 60-79
```

**Interaction contract:**
- Two small inline badges showing category subtotals, only when voice_score_status != "none"
- For text-only sessions (voice_score_status === "none"): show single badge "Content: 85/100" with muted "(text-only)" note
- Uses existing `Badge` component with variant based on score threshold
- Badge color logic: >= 80 use `--strength`, 60-79 use `--chart-3`, < 60 use `--destructive`
- Spacing: 8px gap between badges, 24px vertical gap from score ring above and grid below

**Data source:** `combinedReport.overall_score`, `combinedReport.voice_summary.overall_voice_score`, rubric `content_weight`/`voice_weight` from API response

### 3. Type Extension

**File:** `frontend/src/types/rubric.ts`
**Change:** Add fields to `Rubric`, `RubricCreate`, `RubricUpdate`:
```typescript
content_weight?: number;  // 0-100, default 60
voice_weight?: number;    // 0-100, default 40 (derived)
```
