# Plan 03: Tags System (product/therapeutic_area -> tags)

**Phase:** 22 — Scenarios 模块二次重构
**Decision:** D-03
**Depends on:** Plan 02 (system enums provides predefined tag categories)

## Goal

Replace the fixed `product` and `therapeutic_area` columns on the Scenario model with a flexible `tags` JSON array field. Migrate existing data. Update all frontend consumers (table, editor, API client, types). Predefined tags come from the system_enums table (categories: "product", "therapeutic_area", plus new custom categories).

## Success Criteria

- [ ] Scenario model has `tags` column (Text, JSON array of `"category:value"` strings)
- [ ] `product` and `therapeutic_area` columns removed from Scenario model
- [ ] Data migration converts existing product/therapeutic_area to tags format
- [ ] API response includes `tags: string[]` instead of product/therapeutic_area
- [ ] Frontend scenario table shows tags as colored badges grouped by category
- [ ] Frontend editor allows selecting tags from system_enums categories + freeform input
- [ ] Reports page filter adapts to use tags for product filtering
- [ ] Training page (user-facing) displays scenario tags instead of product field
- [ ] All backend/frontend tests updated for new schema
- [ ] E2E test validates tag creation and display

1. Create Alembic migration `s22b_scenario_tags_migration.py` with TWO steps:

```python
"""Add tags column, migrate data, drop product/therapeutic_area."""

import json
import sqlalchemy as sa
from alembic import op


def upgrade():
    # Step 1: Add tags column
    with op.batch_alter_table("scenarios") as batch_op:
        batch_op.add_column(sa.Column("tags", sa.Text(), server_default="[]", nullable=False))

    # Step 2: Migrate existing data
    conn = op.get_bind()
    scenarios = conn.execute(sa.text("SELECT id, product, therapeutic_area FROM scenarios"))
    for row in scenarios:
        tags = []
        if row.product:
            tags.append(f"product:{row.product}")
        if row.therapeutic_area:
            tags.append(f"therapeutic_area:{row.therapeutic_area}")
        conn.execute(
            sa.text("UPDATE scenarios SET tags = :tags WHERE id = :id"),
            {"tags": json.dumps(tags), "id": row.id},
        )

    # Step 3: Drop old columns
    with op.batch_alter_table("scenarios") as batch_op:
        batch_op.drop_column("product")
        batch_op.drop_column("therapeutic_area")


def downgrade():
    # Reverse: add old columns back, migrate tags data back, drop tags
    with op.batch_alter_table("scenarios") as batch_op:
        batch_op.add_column(sa.Column("product", sa.String(255), server_default=""))
        batch_op.add_column(sa.Column("therapeutic_area", sa.String(255), server_default=""))

    conn = op.get_bind()
    scenarios = conn.execute(sa.text("SELECT id, tags FROM scenarios"))
    for row in scenarios:
        tags = json.loads(row.tags) if row.tags else []
        product = ""
        therapeutic_area = ""
        for tag in tags:
            if tag.startswith("product:"):
                product = tag.split(":", 1)[1]
            elif tag.startswith("therapeutic_area:"):
                therapeutic_area = tag.split(":", 1)[1]
        conn.execute(
            sa.text("UPDATE scenarios SET product = :product, therapeutic_area = :area WHERE id = :id"),
            {"product": product, "area": therapeutic_area, "id": row.id},
        )

    with op.batch_alter_table("scenarios") as batch_op:
        batch_op.drop_column("tags")
```

## Threat Model

| Threat | Mitigation |
|--------|-----------|
| Data loss during migration (product/therapeutic_area values) | Migration converts to tags format; downgrade function restores original columns |
| API consumers break on missing product field | This is an intentional breaking change — all frontend consumers updated atomically in same plan |
| Unconstrained tag values (garbage input) | Tags use `category:value` format; validation in service layer checks format |
| Tag search SQL injection (SQLite LIKE) | Using parameterized queries via SQLAlchemy `text()` with bound params |

## Rollback

- `alembic downgrade -1` restores product/therapeutic_area columns with migrated data
- Revert frontend type changes (restore product/therapeutic_area to Scenario interface)
- Revert API response schema changes
