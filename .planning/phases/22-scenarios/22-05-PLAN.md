# Plan 05: Full-Page Editor (Dialog -> Route-based)

**Phase:** 22 — Scenarios 模块二次重构
**Decision:** D-01
**Depends on:** Plan 04 (skill NOT NULL must be enforced — editor needs updated field requirements)

## Goal

Replace the current Dialog-based scenario editor with a full-page route-based editor matching the HCP Profile Editor pattern. Routes: `/admin/scenarios/new` and `/admin/scenarios/:id`. Layout: single page with Tabs (Basic Info / Linked Config / Scoring Rules), back button top-left, save in header. Remove the old Dialog editor component entirely.

## Success Criteria

- [ ] Route `/admin/scenarios/new` renders the full-page scenario editor in create mode
- [ ] Route `/admin/scenarios/:id` renders the editor in edit mode with data loaded
- [ ] Editor has 3 tabs: Basic Info (name, description, mode, difficulty, tags), Linked Config (HCP, Skill), Scoring Rules (rubric selector + preview + pass threshold)
- [ ] Back button navigates to `/admin/scenarios`
- [ ] Save button in header submits and navigates back to list
- [ ] Archived scenarios redirect to view-only mode (form disabled)
- [ ] List page "Create" button navigates to `/admin/scenarios/new`
- [ ] List page "Edit" action navigates to `/admin/scenarios/:id`
- [ ] Old `scenario-editor.tsx` Dialog component is deleted
- [ ] TypeScript compiles, production build passes
- [ ] E2E test validates create and edit flows via routing

## Tasks

### Task 1: Create Full-Page Scenario Editor Component

**Files:**
- `frontend/src/pages/admin/scenario-editor.tsx` (create)

**Action:**

Create a new page component at `frontend/src/pages/admin/scenario-editor.tsx` following the exact pattern of `hcp-profile-editor.tsx`:

1. **Imports and setup:**
   - `useParams<{ id: string }>()` to determine new vs edit mode
   - `useNavigate()` for back/save navigation
   - `useForm` + `zodResolver` for form validation
   - `useScenario(id)` to load existing data
   - `useCreateScenario()` and `useUpdateScenario()` mutations
   - `useSystemEnums("product")`, `useSystemEnums("therapeutic_area")`, `useSystemEnums("difficulty")`, `useSystemEnums("mode")` for dynamic dropdowns
   - `useHcpProfiles()`, `usePublishedSkills()`, `useRubrics()` for linked entities

2. **Zod schema** (updated for tags + required skill):
```typescript
const scenarioSchema = z.object({
  name: z.string().min(1, t("scenarios.nameRequired")),
  description: z.string().default(""),
  mode: z.string().min(1),
  difficulty: z.string().min(1),
  tags: z.array(z.string()),
  hcp_profile_id: z.string().min(1, t("scenarios.hcpRequired")),
  skill_id: z.string().min(1, t("scenarios.skillRequired")),
  key_messages: z.array(z.string()),
  rubric_id: z.string().min(1, t("scenarios.rubricRequired")),
  pass_threshold: z.number().min(0).max(100),
});
```

3. **Layout structure:**
```tsx
<div className="space-y-6">
  {/* Header: Back button + title + Save button */}
  <div className="flex items-center justify-between">
    <div className="flex items-center gap-3">
      <Button variant="ghost" size="icon" onClick={() => navigate("/admin/scenarios")}>
        <ArrowLeft className="size-4" />
      </Button>
      <div>
        <h1 className="text-2xl font-medium">
          {isNew ? t("scenarios.createButton") : t("scenarios.editTitle", { name })}
        </h1>
      </div>
    </div>
    <Button onClick={form.handleSubmit(onSubmit)} disabled={isArchived}>
      <Save className="size-4" />
      {t("scenarios.save")}
    </Button>
  </div>

  {/* Tabs */}
  <Form {...form}>
    <Tabs defaultValue="basic" className="w-full">
      <TabsList>
        <TabsTrigger value="basic">{t("scenarios.tabBasic")}</TabsTrigger>
        <TabsTrigger value="linked">{t("scenarios.tabLinked")}</TabsTrigger>
        <TabsTrigger value="scoring">{t("scenarios.tabScoring")}</TabsTrigger>
      </TabsList>

      <TabsContent value="basic">...</TabsContent>
      <TabsContent value="linked">...</TabsContent>
      <TabsContent value="scoring">...</TabsContent>
    </Tabs>
  </Form>
</div>
```

4. **Tab: Basic Info** (wrapped in Card):
   - Name (Input, required)
   - Description (Textarea)
   - Mode (radio buttons from system_enums "mode")
   - Difficulty (radio buttons from system_enums "difficulty")
   - Tags (multi-select from system_enums "product" + "therapeutic_area" categories)
   - Key Messages (ObjectionList component)

5. **Tab: Linked Config** (wrapped in Card):
   - HCP Profile selector (Select with Avatar display, from useHcpProfiles)
   - Skill selector (Select from usePublishedSkills, required, shows version + quality badge)
   - SkillStatusBadge for archived skill warning

6. **Tab: Scoring Rules** (wrapped in Card):
   - Rubric selector (Select from useRubrics)
   - Rubric dimension preview (read-only card showing dimensions/weights)
   - Pass threshold input (number, 0-100)
   - "Manage Rubrics" link button → navigates to `/admin/scoring-rubrics`

7. **Data loading:**
   - If `id` param exists: `const { data: scenario, isLoading } = useScenario(id)`
   - Show loading spinner while fetching
   - If scenario.status === "archived": disable all form fields, show info banner

8. **Form submission:**
   - Create mode: call createMutation, on success toast + navigate to list
   - Edit mode: call updateMutation, on success toast + navigate to list
   - Show error toast on failure

## Threat Model

| Threat | Mitigation |
|--------|-----------|
| Direct URL access to archived scenario allows editing | Form disabled state + backend update guard (Plan 01 blocks updates on archived) |
| Race condition: two admins edit same scenario | Backend last-write-wins (standard for this app); could add optimistic locking later |
| Unsaved form data lost on navigation | Browser beforeunload event + form dirty check (optional enhancement) |
