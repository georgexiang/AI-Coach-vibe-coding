# Plan 04: Skill NOT NULL Enforcement

**Phase:** 22 — Scenarios 模块二次重构
**Decision:** D-05
**Depends on:** Plan 03 (tags migration must complete first — both modify the scenarios table)

## Goal

Make `skill_id` a required (NOT NULL) field on the Scenario model. Only published skills can be associated. Update the Alembic migration to handle existing scenarios with NULL skill_id (fail with helpful message). Update frontend form validation to require skill selection.

## Success Criteria

- [ ] `skill_id` column is NOT NULL in the database schema
- [ ] Alembic migration fails gracefully if any scenario has NULL skill_id (with actionable error message)
- [ ] Backend create/update validation requires skill_id (not optional)
- [ ] Frontend editor makes Skill a required field (no "No skill" option)
- [ ] Only published skills appear in the dropdown (archived skills show warning badge)
- [ ] Existing tests updated and passing
- [ ] E2E test validates skill is required on scenario creation

1. Create Alembic migration `s22c_skill_id_not_null.py`:

```python
"""Make skill_id NOT NULL on scenarios table.

Prerequisites: All scenarios must have a skill_id assigned.
If any scenario has NULL skill_id, this migration will fail with a helpful message.
"""

import sqlalchemy as sa
from alembic import op


def upgrade():
    # Pre-check: ensure no NULL skill_ids exist
    conn = op.get_bind()
    null_count = conn.execute(
        sa.text("SELECT COUNT(*) FROM scenarios WHERE skill_id IS NULL")
    ).scalar()

    if null_count > 0:
        # Fetch names for helpful error message
        nulls = conn.execute(
            sa.text("SELECT id, name FROM scenarios WHERE skill_id IS NULL LIMIT 10")
        ).fetchall()
        names = ", ".join(f"'{r[1]}' (id={r[0]})" for r in nulls)
        suffix = f" (and {null_count - 10} more)" if null_count > 10 else ""
        raise Exception(
            f"\n\nMIGRATION BLOCKED: {null_count} scenario(s) have no skill assigned:\n"
            f"  {names}{suffix}\n\n"
            f"ACTION REQUIRED: Assign a published skill to all scenarios via the admin UI "
            f"before running this migration.\n"
            f"  URL: /admin/scenarios (edit each scenario and select a Skill)\n"
        )

    # All clear — alter column to NOT NULL
    with op.batch_alter_table("scenarios") as batch_op:
        batch_op.alter_column("skill_id", nullable=False)


def downgrade():
    with op.batch_alter_table("scenarios") as batch_op:
        batch_op.alter_column("skill_id", nullable=True)
```

## Threat Model

| Threat | Mitigation |
|--------|-----------|
| Migration runs with NULL skill_ids in production | Migration pre-check fails with actionable error listing affected scenarios |
| Admin tries to delete a skill used by scenarios | `ondelete="RESTRICT"` prevents deletion; frontend should show "skill in use" error |
| Orphaned skill_version_id after skill version changes | Version re-pin logic in `_validate_and_pin_skill` always pins to current published version |

## Rollback

- `alembic downgrade -1` makes skill_id nullable again
- Revert schema/model changes to allow null skill_id
- Revert frontend to show "No skill" option
- No data loss (column stays, just becomes nullable again)
