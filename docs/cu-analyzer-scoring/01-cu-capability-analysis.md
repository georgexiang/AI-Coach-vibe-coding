# 01 — CU 能力边界与模态适用性

> 分析 Azure Content Understanding 在不同模态（文本/音频/视频）下的能力与限制，
> 明确哪些评估任务 CU 能做好、哪些做不好。

---

## 1. CU 的设计定位

Azure Content Understanding 是一个**非结构化内容 → 结构化数据** 的提取/生成服务：

```
输入：非结构化内容（文档、音频、视频、图片）
  ↓
处理：基于 Analyzer fieldSchema 定义
  ↓
输出：结构化字段值（string/number/date/array/object）
```

### 核心特征

| 特征 | 说明 | 对评分的影响 |
|------|------|-------------|
| 无状态 | 每次 analyze 调用独立，无记忆 | ✅ 适合独立评估 |
| 单文档处理 | 一次只处理一个输入文件 | ⚠️ 无法对比多文件 |
| Schema 驱动 | 输出完全由 fieldSchema 定义 | ✅ 结果结构可控 |
| 无 system prompt | 不支持额外上下文注入 | ❌ 无法传入评分基准 |
| field description 指导生成 | 生成型字段依赖 description 指令 | ⚠️ 受限于 1024 字符 |

## 2. 各模态能力分析

### 2.1 文档/文本模态 (`prebuilt-documentAnalyzer`)

| 能力 | 说明 | AI Coach 适用性 |
|------|------|----------------|
| 布局提取 | 段落、表格、标题结构 | ❌ 对话无布局 |
| 公式提取 | 数学公式识别 | ❌ 不需要 |
| 字段提取 (extract) | 从文本中提取特定信息 | ⚠️ 有限适用 |
| 字段生成 (generate) | 基于文本内容生成新字段 | ⚠️ 有限适用（见下文） |
| 语义理解 | 理解文本含义 | ⚠️ 有限 — 无法接收外部评分标准 |

**对 AI Coach 的文本评分结论:**

CU 处理 transcript 时的**根本限制**:
1. **无 system prompt**: 不能告诉 CU "只评估 role=user 的内容"
2. **无外部上下文**: 不能告诉 CU "产品是 Zanubrutinib，key messages 是 X/Y/Z"
3. **field description 限制 1024 字符**: 无法嵌入完整的 scenario 信息
4. **不理解对话角色**: 把 MR 和 HCP 的文本等同对待

**CU 文本评分能做到的:**
- 判断文本是否"看起来像医药对话" (泛泛的内容分类)
- 评估整体对话的结构性/完整性 (不区分角色)
- 生成通用的改进建议 (缺乏针对性)

**CU 文本评分做不到的:**
- 判断 MR 是否完成了特定任务 (需要 key messages 上下文)
- 判断 MR 是否展示了正确的产品知识 (需要知道什么是"正确的")
- 判断 MR 是否恰当处理了异议 (需要知道 HCP 的异议设定)
- 区分 MR 表现和 HCP 引导 (无角色理解)

### 2.2 音频模态 (`prebuilt-audioAnalyzer`)

| 能力 | 说明 | AI Coach 适用性 |
|------|------|----------------|
| 语音转文字 | 高质量 ASR | ✅ 获取 transcript |
| 说话人分离 | 识别不同说话人 | ✅ 区分 MR/HCP 语音 |
| 语音质量分析 | 流畅度、语速、停顿 | ✅ **非常适合** |
| 情感/语调检测 | 语音情绪分析 | ✅ 适合 |
| 关键词/短语检测 | 从音频中提取关键信息 | ⚠️ 有限适用 |

**对 AI Coach 的语音评分结论:**

CU 的音频分析**天然适合**以下评分维度:

| 维度 | CU 适合度 | 原因 |
|------|-----------|------|
| fluency (流畅度) | ✅ 完美 | 纯语音信号分析，无需外部上下文 |
| tone (语调) | ✅ 完美 | 声学特征分析 |
| pace (语速) | ✅ 完美 | 时间序列分析 |
| pronunciation (发音) | ✅ 完美 | 声学模式匹配 |

**为什么 CU 适合语音评分:**
- 语音质量是**内在属性** — 不需要知道"MR应该说什么"，只需评估"MR怎么说的"
- 音频信号本身包含全部评估信息
- 不存在"角色混淆"问题 — 可以基于说话人分离单独评估 MR 的语音
- 不需要 scenario-specific 上下文

### 2.3 视频模态 (`prebuilt-videoAnalyzer`)

| 能力 | 说明 | AI Coach 适用性 |
|------|------|----------------|
| 视觉分析 | 场景理解、动作识别 | ⚠️ 未来可用 |
| 多模态理解 | 视频 + 音频综合 | ⚠️ 未来可用 |
| 分段分析 | 15-30s 片段逐段评估 | ⚠️ 未来可用 |
| 人脸/手势 | 面部表情、肢体语言 | 🔮 Avatar/F2F 场景潜力 |

**当前状态:** AI Coach 平台暂未使用视频评分，但未来如果增加 Avatar 视频录制，
CU 的视频分析能力可评估 MR 的肢体语言、表情管理等非语言沟通维度。

## 3. CU 的关键技术限制

### 3.1 Field Description 限制

| 属性 | 限制值 | 来源 |
|------|--------|------|
| description 长度 | **≤ 1,024 字符** | Azure Service Limits (2026-02 更新) |
| field name 长度 | ≤ 64 字符 | |
| analyzer ID | ≤ 64 字符，仅字母数字+点+下划线 | |

**实际影响:** 1024 字符无法容纳:
- 4 条 key messages 的完整内容 (~200-400 字符)
- HCP Profile 的人格描述 (~300 字符)
- 产品信息 + 治疗领域 (~100 字符)
- 评分指令和输出格式要求 (~200 字符)

总计需要 ~800-1000 字符仅用于上下文，留给评分指令的空间极其有限。

### 3.2 无上下文注入机制

**CU 与 LLM 的关键差异:**

| 机制 | LLM | CU |
|------|-----|-----|
| System prompt | ✅ 任意长度上下文 | ❌ 不支持 |
| Few-shot examples | ✅ 可嵌入示例 | ❌ 不支持 |
| 动态指令 | ✅ 每次调用可变 | ❌ Schema 固定 |
| 角色定义 | ✅ 可指定评估对象 | ❌ 无此概念 |

CU 的 Analyzer 是**一次定义、多次调用**的模式。fieldSchema 在创建时固定，
后续每次 analyze 调用只能传入不同的文档/音频，**不能改变评估规则**。

这意味着: **每个 scenario 的评分标准不同（不同产品、不同 key messages），
但 CU analyzer 是按 rubric 创建的，无法按 scenario 定制。**

### 3.3 Standard vs Pro 模式

| 模式 | 特点 | AI Coach 适用性 |
|------|------|----------------|
| Standard | 单文件、快速、成本低 | ✅ 当前使用 |
| Pro | 多文件、多步推理、更强上下文 | 🔮 **可能解决部分问题** |

**Pro 模式的潜力:**
- 支持"多文件 + 参考数据"输入 — 可能允许传入 scenario metadata 作为参考
- 支持"多步推理" — 可能能理解更复杂的评估指令
- **当前限制:** 仅支持 PDF/TIFF/图片，暂不支持 JSON 文本

### 3.4 文件格式与大小限制

| 模态 | 支持格式 | 大小限制 | 时长限制 |
|------|---------|---------|---------|
| 文档 | PDF, DOCX, XLSX, TXT, HTML, MD, JSON | 200MB (直传) / 4GB (URL) | N/A |
| 音频 | WAV, MP3, M4A, FLAC, OGG, OPUS | 200MB (直传) / 4GB (URL) | 4h (URL) |
| 视频 | MP4, MOV, AVI, FLV, MKV | 200MB (直传) / 4GB (URL) | 30min (直传) / 2h (URL) |
| 图片 | JPG, PNG, BMP, HEIF | 200MB | 50×50 ~ 10000×10000 px |

**对 AI Coach 的影响:**
- Transcript JSON 通常 < 100KB，远在限制内
- 音频录音通常 5-30 分钟，WebM/WAV 格式需确认支持
- 50MB 前端上传限制在 CU 限制范围内

## 4. CU 适合/不适合的评估任务分类

### ✅ CU 适合的评估任务

| 任务类型 | 原因 |
|----------|------|
| 音频质量评估 | 纯信号分析，无需外部上下文 |
| 语音流畅度 | 内在属性，自包含 |
| 发音准确性 | 声学模式匹配 |
| 语速/节奏 | 时间序列特征 |
| 语调/情感 | 声学特征 |
| 文档格式检查 | 结构性分析 |
| 简单分类 | 是/否判断，无复杂推理 |

**共同特征:** 评估标准**完全包含在输入内容本身中**，不需要外部"正确答案"参照。

### ❌ CU 不适合的评估任务

| 任务类型 | 原因 |
|----------|------|
| 目标完成度评估 | 需要知道"目标是什么" |
| 角色行为评估 | 需要理解"谁应该做什么" |
| 知识准确性评估 | 需要"正确知识"作为参照 |
| 上下文相关性评估 | 需要知道"相关的上下文是什么" |
| 任务达成评判 | 需要 key messages 等外部标准 |
| 对比性评估 | 需要对比多个 session 或基准 |

**共同特征:** 评估需要**外部上下文/参照标准**，不能仅从输入内容本身判断好坏。

## 5. 总结: CU 的正确使用定位

```
CU 的能力模型:

  输入内容 ──► CU Analyzer ──► 结构化输出
     │                            │
     │  ❌ 无法注入               │  ✅ 格式可控
     │  - 外部评分标准            │  - JSON 结构
     │  - 任务目标                │  - 分数 + 反馈
     │  - 角色定义                │  - 维度化
     │  - 正确答案参照            │
     │                            │
     ▼                            ▼
  CU 只能评估"内容本身的        CU 不能评估"内容是否
   固有属性"                    满足外部期望"
```

**一句话结论:** CU 适合评估"怎么说"（语音质量），不适合评估"说了什么"（内容正确性/完整性）。
